# X 数据来源公开发布检查

当前采集器使用网页登录会话读取时间线和详情。公开或收费之前，需要在约定用途下验证官方 X API 或明确授权的数据源。本项目未将现有网页登录凭证用于官方 API，也没有自动切换生产采集。

## 已核对的接口契约

[X User Posts](https://docs.x.com/x-api/users/get-posts) 提供用户时间线和分页。以下是文档中存在的字段；能否在指定套餐、账号和样本上完整返回，仍需实测。

| 场景 | 对应字段 | 样本验收 |
| --- | --- | --- |
| 普通推文与翻页 | `id`、`text`、`created_at`、`pagination_token` / `since_id` | 相同窗口无漏项和重复；无新内容和请求失败分开报告 |
| 长文和文章 | `note_tweet`、`article`、`article.cover_media` | 正文末尾、段落和封面都与 X 原文一致；短摘录标记为不完整 |
| 引用、转推和回复 | `referenced_tweets`、`referenced_tweets.id`、`conversation_id` | 保留原作者和原文 ID，缺失引用不转成博主本人观点 |
| 图片和多图 | `attachments.media_keys`、媒体扩展 | 原图顺序和引用图归属一致；失效链接和缺图可发现 |

## 接入前的实测与成本

1. 用独立的开发者项目和已确认用途的凭证，选 2–3 位样本博主；覆盖普通推文、长文、引用和图片。用小批次核对相同时间窗和原文。设置可接受的花费上限，并记录实际账单计量，而非用网页请求次数估算。
2. 验证已删除或不再可用的帖子能停止展示。核对原文、引用、截图之外的原始媒体、离线归档和再分发权限。核对适用协议后，再确定 PostgreSQL、对象存储和搜索索引的同步清理范围。参见 [X 开发者政策](https://docs.x.com/developer-terms/policy)。
3. 按月估算 **X 资源读取 + 文本与视觉模型 + 嵌入/重排 + 存储与服务**。例如 3 位作者每天各 5 条，30 天约 450 条新内容。只按公开的 Posts Read 示例费率 `$0.005/资源`，这部分约 `$2.25/月`；不含额外读取、媒体相关请求、模型或基础设施。最终以 [X API 计费说明](https://docs.x.com/x-api/getting-started/pricing) 和开发者控制台实际用量为准。运行监控会记录文本模型调用和 token，并与图片用量分开显示。
4. 核对准入、原文展示和撤除流程后再规划收费。当前没有证据证明真实账号覆盖达标，也没有用文档示例响应替代线上实测。
